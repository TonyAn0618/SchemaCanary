# Governance

SchemaCanary is currently maintained by its project creator.

- Small, backward-compatible fixes may be accepted directly after tests pass.
- New public interfaces, report-schema changes, provider adapter contracts, telemetry, hosted
  services, and breaking changes require a written issue, RFC, or architecture decision record.
- Decisions are based on reproducible evidence, user value, security, maintenance cost, and the
  current project scope.
- Commercial relationships, sponsorships, or vendor support must be disclosed and may not alter
  compatibility conclusions.

Before adding a second maintainer, this file must define nomination, permissions, removal, release
authority, security handling, and conflict-resolution procedures. At least two people should be
able to release and respond to incidents before the project describes itself as ecosystem-critical.
